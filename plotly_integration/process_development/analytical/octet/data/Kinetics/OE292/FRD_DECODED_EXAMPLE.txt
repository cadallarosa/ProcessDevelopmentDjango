================================================================================
BASE64 DECODING PROCESS (Detailed)
================================================================================

STEP 1: Base64 String
----------------------
AssayXData (first 60 characters):
"AAAAAM3MTD7NzMw+I9sZP83MTD8AAIA/mpmZPzMzsz+R7cw/ZmbmP2IQAEDN..."

This is a text encoding of binary data.

STEP 2: Decode Base64 to Binary
--------------------------------
Python code:
    binary_data = base64.b64decode(base64_string)

Result: Binary bytes (hexadecimal representation):
00 00 00 00 CD CC 4C 3E CD CC CC 3E 23 DB 19 3F CD CC 4C 3F 00 00 80 3F ...

Each group of 4 bytes = one 32-bit float

STEP 3: Unpack Binary as IEEE 754 Floats
-----------------------------------------
Python code:
    num_floats = len(binary_data) // 4  # 4 bytes per float
    float_format = f'<{num_floats}f'    # '<' = little-endian, 'f' = float
    floats = struct.unpack(float_format, binary_data)

Binary bytes → Float values:
    00 00 00 00  →  0.0
    CD CC 4C 3E  →  0.2
    CD CC CC 3E  →  0.4
    23 DB 19 3F  →  0.601
    CD CC 4C 3F  →  0.8
    00 00 80 3F  →  1.0
    ...

STEP 4: Create NumPy Array
---------------------------
Python code:
    time_array = np.array(floats)

Result: NumPy array ready for analysis
    array([0.   , 0.2  , 0.4  , 0.601, 0.8  , 1.   , ...])

================================================================================
TYPICAL SIGNAL PATTERNS
================================================================================

REGENERATION (Glycine):
  Signal: Negative, decreasing
  Range: 0 to -1.5 nm
  Meaning: Stripping bound material

NEUTRALIZATION (PBS):
  Signal: Positive, stable
  Range: 2.7 to 2.9 nm
  Meaning: Returning to neutral pH

LOADING:
  Signal: Positive, strongly increasing
  Range: 2 to 17 nm (gain ~15 nm)
  Meaning: Antibody accumulating on sensor

BASELINE:
  Signal: Small changes, stabilizing
  Range: ±0.5 nm around loaded value
  Meaning: Signal equilibration before analyte

ASSOCIATION:
  Signal: Positive, increasing (curve)
  Rate: Fast initially, slows over time
  Meaning: Analyte binding to antibody (kon kinetics)

DISSOCIATION:
  Signal: Decreasing (decay curve)
  Rate: Exponential decay
  Meaning: Analyte unbinding from antibody (koff kinetics)

================================================================================
KINETIC PARAMETERS EXTRACTED FROM CURVES
================================================================================

From ASSOCIATION curve:
  - kon (association rate constant)
  - Amplitude (maximum binding)
  - Curve shape

From DISSOCIATION curve:
  - koff (dissociation rate constant)
  - t1/2 (half-life of complex)
  - Decay shape

Calculated:
  - KD = koff / kon (equilibrium dissociation constant)
  - Lower KD = tighter binding = better antibody

================================================================================
HOW DATA FLOWS TO DATABASE
================================================================================

1. FRD XML File (one per sensor)
   ├─ 132 steps
   └─ Each step: metadata + Base64 data

2. FRDParser.parse_all_steps()
   ├─ Decodes Base64 → NumPy arrays
   └─ Returns list of step dictionaries

3. FRDImporter.import_dataset()
   ├─ Creates OctetExperiment record
   ├─ Creates OctetSensorData record
   └─ For each step:
       ├─ Creates OctetStepData record
       └─ Bulk creates OctetTimeSeriesData records
           (one row per time point)

4. Database Structure:
   OctetExperiment (1 row)
     └─ OctetSensorData (1 row per sensor)
          └─ OctetStepData (132 rows for this sensor)
               └─ OctetTimeSeriesData (~40,000 rows!)

Alternative (Optimized):
   OctetKineticsExperiment (1 row)
     └─ OctetKineticsSensor (11 rows, one per antibody)
          ├─ loading_data: JSON array
          ├─ baseline_data: JSON array
          ├─ association_data: JSON array
          └─ dissociation_data: JSON array

================================================================================
KEY INSIGHTS
================================================================================

1. FRD files store time series as IEEE 754 binary floats encoded in Base64
   - Efficient storage (4 bytes per value)
   - Exact numerical precision
   - Platform-independent format

2. Little-endian byte order is standard for Intel/AMD processors
   - Least significant byte first
   - Struct format: '<f' for little-endian float

3. One FRD file = one sensor's complete data
   - Multiple cycles per file
   - Each cycle = one antibody test
   - Thousands of time points per cycle

4. Signal measured in nanometers of optical thickness
   - Biolayer interferometry principle
   - Higher signal = more material on sensor
   - Typical antibody loading: 10-20 nm

5. Standard sampling rate: 5 Hz (0.2 second intervals)
   - Fast enough for kinetics (seconds to minutes)
   - Generates large datasets (40k+ points per sensor)

6. Database storage trade-off:
   - Individual rows: Maximum compatibility, flexible queries, HUGE size
   - JSON storage: Compact, fast, less flexible queries
